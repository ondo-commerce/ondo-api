# 미수 원장 쓰기 전략 — 측정 기록

같은 거래처에 정산 쓰기가 동시에 몰릴 때 장부가 틀어지는지, 그리고 그걸 막는 값이 얼마인지
재고 골랐다(MUL-143).

```
load/settlement/
  README.md                        이 문서
  results/strategy-comparison.md   전략 비교 표 (하네스가 덮어쓴다)
```

하네스는 코드 쪽에 있다 — `wholesale-api/src/test/java/com/ondo/wholesale/settlement/LedgerStrategyMeasurement.java`

---

## 문제 — 잠금은 값이 아니라 **순서**를 지킨다

미수는 출고·입금·입금취소·배분 **네 경로**에서 바뀐다.

흔한 실수는 잔액을 한 칸에 두고 `UPDATE` 하는 것이다. 그러면 둘이 같이 읽고 같이 써서 하나가
덮어써진다(Lost Update). **우리는 그걸 안 한다** — 원장을 추가 전용으로 두고 줄마다 그 시점
잔액을 같이 적는다. 칸을 안 고치니 덮어쓸 것도 없다.

그런데 문제가 없어지지 않는다. **두 요청이 같은 잔액을 읽고 각자 이어 쓰면** 두 줄의
`balance_after` 가 같은 값에서 출발한다. 줄은 다 남는데 **줄마다 적어 둔 잔액이 거짓말이 된다** —
"왜 이 숫자인지" 를 설명하려고 만든 장부가 설명을 못 하게 된다.

> 그래서 여기 잠금은 **값을 지키는 게 아니라 순서를 지킨다.**

## 잰 것

| | |
|---|---|
| 조건 | 같은 거래처에 동시 16 세션 × 40 건 = **640 건**, 전부 +1,000 |
| 전략 | A 잠금 없음 · B 낙관적 락 · C 비관적 락(지금) |

전부 같은 금액이라 정상이면 `balance_after` 가 하나씩 다르다 — **중복 하나가 틀어진 순서 하나**다.

결과는 [`results/strategy-comparison.md`](results/strategy-comparison.md).

| 전략 | 요약 잔액 | 순서 오류 | 충돌·재시도 | 못 넣음 | 걸린 시간 |
|---|---:|---:|---:|---:|---:|
| A 잠금 없음 | **70,000** | **570** | 0 | 0 | 318 ms |
| B 낙관적 락 | 639,000 | 0 | **4,556** | **1** | 1,180 ms |
| **C 비관적 락 (지금)** | **640,000** | **0** | 0 | 0 | 356 ms |

기대 잔액은 640,000 이다.

### A — 잠금을 빼면 실제로 깨진다

**잔액의 89% 가 증발했다**(640,000 → 70,000). 줄은 640 개가 다 남아 있는데 요약 잔액이 틀렸다.
순서 오류 570 건 — 640 건 중 대부분이 같은 출발점에서 겹쳤다.

테스트가 무엇을 막고 있는지 알려면 **막는 걸 빼봐야 한다.** 이 줄이 그 확인이다.

### B — 낙관적 락은 이 자리에 안 맞는다

정확성은 지킨다(순서 오류 0). 그런데 대가가 크다.

- **충돌 4,556 회** — 640 건을 넣으려고 5,000 번 가까이 다시 했다. 건당 7 번꼴
- **1 건은 끝내 못 넣었다** — 재시도 한도(50 회)를 넘겼다
- 시간이 **3.3 배**

마지막이 치명적이다. **출고는 했는데 미수에 안 잡히는 건이 생긴다.** 돈이 걸린 자리에서
"가끔 한 건은 못 넣습니다" 는 받아들일 수 없다.

낙관적 락은 **충돌이 드물 때** 쓰는 방법이다. 정산은 같은 거래처에 쓰기가 몰리는 구조라
전제가 안 맞는다.

### C — 비관적 락을 고른 이유

정확하고, **잠금 없는 것보다 38ms 느릴 뿐이다**(318 → 356ms). 뒤에 선 요청이 기다리지만
헛일을 안 하므로 총 시간이 낙관적의 1/3 이다.

기다리는 비용이 싼 이유는 **잠금 안에서 하는 일이 적어서**다 — 원장 쓰기 말고 아무것도 하지
않는다. 여기서 외부 호출이라도 하면 이 숫자가 뒤집힌다.

## 재현

측정은 평소에 안 돈다. 스레드를 여럿 띄우고 결과를 파일로 내보내서 일반 테스트와 섞이면 안 된다.

```bash
cd wholesale-api
./gradlew test --tests '*LedgerStrategyMeasurement*' -Dmeasure=true
```

Testcontainers 로 빈 PostgreSQL 을 띄우므로 로컬 DB 가 필요 없다. 결과가
`load/settlement/results/strategy-comparison.md` 에 덮어써진다.

전략은 설정으로 바꾼다 — 셋을 비교하려면 **같은 조건**에서 돌려야 하고, 전략마다 앱을 다시
띄우면 데이터도 상태도 매번 달라진다.

```yaml
ondo:
  settlement:
    ledger:
      strategy: PESSIMISTIC   # NONE · OPTIMISTIC · PESSIMISTIC
```

## 측정하며 고친 것

**스레드 안의 예외가 조용히 사라졌다.** 처음 돌렸을 때 원장 줄이 0 인데 "성공" 으로 끝났다.
`ExecutorService.submit` 은 예외를 `Future` 에 담아 두는데 아무도 안 꺼내 보면 그대로 묻힌다.
붙잡아서 밖으로 던지게 고쳤다.

> 측정이 **0 건으로 끝났는데 초록색이면** 그건 결과가 아니라 사고다.
